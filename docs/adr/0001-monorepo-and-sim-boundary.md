# ADR-0001: Монорепо pnpm и граница симуляции

Дата: 2026-11-04 · Статус: принято

## Контекст
Канон требует монорепо и детерминированное ядро, отделённое от рендера/UI. Нужен срез M0–M5, который собирается и тестируется одним агентом/командой.

## Решение
- pnpm workspaces: `apps/web` (React 19 + Vite + Three.js), `packages/sim` (чистая TS-симуляция), `packages/data` (JSON-контент + zod).
- `sim` не импортирует DOM/Three/React; UI и рендер импортируют `@sf/sim` через `src/index.ts`.
- Один корневой `tsconfig.json` (strict) + алиасы `@sf/sim`, `@sf/data`; Vite резолвит их в исходники — один типчек на весь репозиторий.

## Последствия
+ Один `pnpm typecheck/test`, быстрый цикл, невозможно «забыть» пакет.
+ Симуляция тестируется headless (Vitest, node), без браузера.
− `apps/api`, `packages/render`, `packages/ui`, `packages/protocol` не выделены в отдельные пакеты в срезе; их код живёт в `apps/web`. Это зафиксировано в NEXT.md как долг перед M11 (сеть).
