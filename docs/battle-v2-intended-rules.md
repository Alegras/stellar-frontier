# Бой v2 «Сетка командования»: предполагаемые правила (извлечение из промпта)

> **Назначение:** справочник «как должно быть» для починки багов «Завершить ход не запускает врага» и «Авто-бой всегда проигрывает». Собран из Части XVI и XV промпта. Источник правды — сам промпт; этот файл — сжатая выжимка с точными ссылками.
> **Приоритет источников:** `16b_turn_ap_rules.md` — числа и правила v2 (авторитет); `16_battle_v2_addendum.md` §8 фиксирует спорные решения; `15a_grid_battle_rules.md` — формулы урона/местность/гексы/победа (переносится без изменений); `16c` — UI/HUD; `16d` — автомат состояний/команды; `16e` — ИИ и паритет. Часть XV в остальном — **архив** [16a §5, 16 §2].

## 0. Ключевые инварианты

- Раунд = **фаза игрока → фаза противника → конец раунда**; первая сторона в раунде 1 — по средней инициативе, далее **чередование** [16b §1.2–1.3].
- **2 AP** на юнит за фазу (элита/флагман — 3, максимум 3), остаток сгорает, в минус нельзя [16b §2.1, §2.9; 16d §1.2].
- Юнита выбирает **игрок** (любой свой юнит с AP > 0, в любом порядке), а не очередь по инициативе [16b §3.1–3.3; 16 §0].
- Инициатива больше **не** задаёт порядок юнитов — только первую сторону, порядок реакций и тай-брейки [16b §6.2].
- Движение и атака — в любом порядке внутри AP (движение→атака, атака→движение, двойное движение, двойная атака) [16b §4.1].
- Сетка существует **только на стратегической карте L0**; в системе — real-time 6DOF [16b §1.9; 16 §0].
- Детерминизм: `seed` + журнал команд → идентичный бой и реплей, без `Math.random` [16b §10.2 #14; 16c шапка].

## 1. Структура хода: раунд, фазы, инициатива

| Элемент | Правило | Ссылка |
|---|---|---|
| Раунд | фаза A (игрок) + фаза B (противник) + конец раунда | 16b §1.2 |
| Порядок юнитов в фазе | **произвольный**, любая последовательность при хватающем AP; Tab — цикл по инициативе | 16b §3.1–3.4 |
| Первая сторона, раунд 1 | больше средней инициативы живых юнитов; при равенстве — атакующий; сценарий может фиксировать (`first_side_override`) | 16b §1.3, §6.1 |
| Первая сторона, раунды 2+ | **чередование**: кто ходил вторым — ходит первым | 16b §1.3 |
| Инициатива — три роли | первая сторона р.1; порядок реакций (overwatch/ответы); тай-брейки `hash(seed, round, stack)` | 16b §6.2–6.3 |
| Фаза длится | до исчерпания AP, до «Завершить ход», до таймера (MP) или авто-конца | 16b §1.4 |
| Конец раунда (детерминировано) | статусы −1 → реген щита +3% (если не было урона) → КД −1 → +1 ОК → тик мин/эффектов → проверка победы → раунд+1 | 16b §1.5 |
| Кап раундов | 25 (стандарт), 30 (оборона станции); с раунда 16 урон +25%, затем +10%/раунд | 16b §1.8 |
| Пустая фаза | сторона не сделала действий 2 фазы подряд → предупреждение, затем авто-конец | 16b §1.8 |
| Автомат состояний | IDLE → UNIT_SELECTED → MOVE_PREVIEW/TARGET_SELECT → RESOLVING_* → REACTION → IDLE; `endPhase` из IDLE → PHASE_ENEMY → ROUND_END | 16d §1.1 |

## 2. Экономика AP (2 AP на юнит за фазу)

| Действие | AP | Ограничение | Ссылка |
|---|---|---|---|
| Движение (до MP гексов) | 1 | местность и LOS как в XV §7 | 16b §2.2 #3 |
| Второе движение (марш) | 1 | +50% MP, суммарно ≤ 1.5×MP за фазу | 16b §2.2 #4, §2.3 |
| Атака (ближняя/дальняя) | 1 | цель валидна | 16b §2.2 #5 |
| Вторая атака за фазу | 1 | **−15% урона**; ответного удара нет (ответ уже был) | 16b §2.4, §8 п.6 |
| Классовая способность | 1 | КД = 0, 1 использование/фаза | 16b §2.2 #7 |
| Адмиральская способность | 1–2 AP + 1–2 ОК | ≤ 2 адмиральских за **раунд** | 16b §2.2 #8, §2.6 |
| Защита | 1 | +20% DEF + 10% реген щита до своей следующей активации | 16b §2.7 |
| Overwatch | 2 | один выстрел 75% по первому врагу, движущемуся в LOS | 16b §2.7, §4.5 |
| Отступление юнита / вывод в резерв | 2 | уход в резерв с 50% HP | 16b §2.2 #14–15 |
| Абордаж / ремонт | 1 | 1/бой | 16b §2.2 #12–13 |
| Ожидание (пропуск) | 0 | юнит сохраняет AP, действует позже в этой же фазе | 16b §2.2 #17 |
| Инспекция, «Завершить ход», реакции | 0 | не действия юнита | 16b §2.8 |
| Перенос остатка AP | **запрещён** | AP сгорают в конце фазы | 16b §2.1, §5.2 |

Запреты: AP не копится между фазами, не уходит в минус, нельзя получать AP от союзника [16b §2.9]. Элита (3+ шеврона) и флагман — 3 AP, баффы выше 3 не дают [16b §2.1; 16d §1.2].

## 3. «Завершить ход»: что кнопка обязана делать

| # | Требование | Ссылка |
|---|---|---|
| 1 | Кнопка **всегда доступна** в фазе игрока (даже при остатке AP); недоступна только во время анимации; в фазе врага заменяется бейджем «Ход противника» | 16b §5.1; 16c §6.1 |
| 2 | Горячие клавиши `Space`/`Enter`; `Ctrl+Enter` — без предупреждения | 16c §6.2; 16b §5.1 |
| 3 | При AP > 0 — предупреждение (inline-полоса, а не модалка) с числом AP и юнитов; второй клик/Enter — подтверждение | 16b §5.3; 16c §6.3 |
| 4 | Остаток AP **сгорает**, в лог: «сожжено N AP» | 16b §5.2 шаг 2, §5.7 |
| 5 | Защита и overwatch **сохраняются** до конца фазы врага | 16b §5.2 шаг 3 |
| 6 | **Фаза переходит противнику; его юниты получают AP и ИИ обязан отыграть всю свою фазу** | 16b §5.2 шаг 4, §1.4; 16 §5 |
| 7 | После фазы врага — конец раунда и **возврат управления игроку в начале нового раунда** | 16b §1.2, §1.5; 16c §6.6 |
| 8 | Лог фазы: `phase`, `side`, `ap_total/spent/burned`, `actions`, `reactions`, `end_reason` (manual/auto/timeout) | 16b §5.7 |
| 9 | Двойной клик игнорируется (дебаунс 0.5 с); победа в момент завершения — бой кончается, фаза не переключается | 16b §5.8 |
| 10 | Авто-завершение — опция: AP=0 у всех → через 1.5 с (UI: 0.8 с с отменой) авто-конец; не завершает фазу при остатке AP | 16b §5.4; 16c §6.4 |
| 11 | Таймер фазы в MP/коопе 90 с → авто-«Завершить ход» (`end_reason=timeout`) | 16b §5.5; 16d §1.5 |
| 12 | `endPhase` идемпотентен: если сторона уже переключена — повторная команда ничего не делает | 16d §4.6 |

Переход фазы в UI: баннер «ФАЗА ПРОТИВНИКА» 900 мс → ход ИИ (быстрый/пропуск) → 300 мс → «ВАША ФАЗА · Раунд N+1» с автовыбором юнита [16c §6.6]. В фазе врага игрок не действует, но может инспектировать и читать журнал [16c §6.6].

## 4. Фаза ИИ противника: обязательное поведение

| Требование | Ссылка |
|---|---|
| ИИ планирует **всю фазу**: порядок юнитов + распределение 2 AP, а не один юнит по очереди | 16e §4.1–4.2 |
| Порядок (sequencing): сначала добивающие цель, затем снайперы/малоуязвимые, затем приманки под overwatch, последними безопасные | 16e §4.4 |
| Трата AP по ситуации: добивание → атака+атака; подход → движение+атака; под фокусом → защита/отход; не достаёт → сближение | 16e §4.3 |
| Overwatch ставится и учитывается в оценке (не более 2 юнитов стороны в overwatch) | 16e §4.5; 16b §4.5 |
| ИИ **сам завершает ход**, когда все AP = 0, все оценки ≤ 0 или действие ухудшает позицию; порог «не тратить AP на ерунду» 0.15 | 16e §4.6; 16b §10.1 |
| Фаза не может «просвистеть»: максимум 30 действий на фазу, затем принудительный конец — это защита от зависания, **не** способ пропустить фазу | 16b §10.1 |
| Сложность меняет **качество решений**, не числа: запрещены бонусы к урону/HP, лишние AP, знание скрытого резерва, ход вне фазы, подкрутка бросков | 16e §4.7 |
| ИИ должен **атаковать**, а не только двигаться, если цель достижима (атака — приоритетное действие; фокус на повреждённом юните −30% HP, kill-order) | 16b §10.1; 15d §5.1 |
| Детерминизм решений: `hash(seed, round, side, stack)`, без `Math.random` | 16b §10.1 |
| Бюджет времени: фаза ≤ 400–450 мс, действие ≤ 15 мс (деградация — отключить 2-opt, сузить кандидатов) | 16e §4.9; 16b §10.1 |
| Приёмка: «Фаза противника наступает после конца хода; раунд сменяется» и «ИИ v2 играет фазу осмысленно» | 16 §5; 16b §10.3 |

Ключевой контракт: после нажатия «Завершить ход» **должен произойти вражеский ход (движения/атаки/способности), видимый в логе и на поле**, и только потом управление возвращается игроку в новом раунде [16b §1.4, §5.2; 16c §6.6; 16 §5 демо].

## 5. «Авто-бой», авторезолв, паритет и winrate

- **Игровой путь для ИИ-боя — авторезолв, а не отдельный «быстрый ИИ».** В таблице слоёв: «Оффлайн/ИИ-бой → авторезолв», HUD v2 для него не применяется [16c §0.5]. Аварийное завершение боя (`battle:abort`) переводит бой в **детерминированный авторезолв остатка** [16d §2.3, §9.4].
- **Паритет обязателен:** сетка v2 против авторезолва — потери в пределах **±10%** на 14 сценариях × 200 прогонов; v1↔v2 — ±15%; ≥90% прогонов в допуске, mean |Δ| ≤ 0.05/0.08, согласие исхода ≥85% [16b §8.6; 16e §5.1–5.3; 15a §10.6]. Равный бой 100/100 FP: авторезолв 57% потерь, цель сетки — 52–63% [16b §8.6].
- **Скрытая коррекция запрещена:** «подтягивать итог v2 к авторезолву постфактум» нельзя [16e §5.4]. Поэтому показатель «≈ авторезолв по потерям» обязан считаться из формулы авторезолва (GDD §11.6), а не из фактического результата боя.
- **Winrate не может быть 100/0.** При равном FP целевой коридор: Разведка 72–80%, Ветеран 50–58%, Адмирал 32–40% побед игрока [15d §10.1]. Тактика меняет исход на 20–25 п.п., но не отменяет соотношение сил: при FP 0.5 игрок не может побеждать «Адмирала» в 40% [15d §10.2].
- Зеркальный бой (одинаковый мультимножество классов/статов у сторон) обязан давать ≈50% при равном ИИ; стабильные 0% или 100% — это дисбаланс/асимметрия кода, а не «сложность» [15d §10.1–10.2; 16e §4.7].
- **ИИ за игрока — не «штрафной»:** заместитель (AFK/дисконнект/ИИ-командующий) играет обычным профилем («Защитник» — наименее рискованный), без бонусов и без деградации качества; не отступает без согласия (только при loss > 0.7) [15d §9.3; 16b §5.8; 16e §4.7].
- Санити по длительности: 6–10 раундов, 90–180 с, ≤10% «пустых» действий [15d §10.3; 15a §11.1]. Результат воспроизводим по seed, отчёт с потерями и обоснованием [промпт M4/M5: «Автобой 10 на 10 даёт отчёт… воспроизводим по seed»].

## 6. Гекс-геометрия (обязательный контракт)

| Параметр | Правило | Ссылка |
|---|---|---|
| Поле | **15 колонок × 11 рядов = 165 гексов**, pointy-top (вершина вверх), раскладка **odd-r** (нечётные ряды сдвинуты вправо) | 15a §2.1; 15c §1.1 |
| Хранение | **axial (q,r)** — все алгоритмы; **cube (x=q, z=r, y=−x−z)** — расстояние/LOS; **offset (col,row)** — только отрисовка и ввод | 15a §2.2; 15c §1.1 |
| Пересчёт | `col = q + (r − (r&1))/2`, `q = col − (row − (row&1))/2`; `toCube: x=q, z=r, y=−q−r` | 15a Прил. A.1; 15c §1.1 |
| Соседи | 6 направлений **в axial**: `(+1,0),(+1,−1),(0,−1),(−1,0),(−1,+1),(0,+1)`; offset-таблицы смещений в коде — недопустимы | 15c §1.2; 15a Прил. A.2 |
| Расстояние | `dist = max(|dq|, |dr|, |dq+dr|)` (cube-метрика, `hexDistance`); 1 гекс = 400 м | 15a §2.2, Прил. A.2; 15c §1.2 |
| Инварианты | `d(a,a)=0`, симметрия, неравенство треугольника, **«d = 1 ⟺ входит в neighbors»** (property-тест) | 15c §1.2 |
| Пиксели | `x = 40 + 48q + (r&1)·24`, `y = 32 + 42r` (native px, шаг 48/42); picking — обратное + cube-round | 15a §2.1, Прил. A.5 |
| Стоимость гекса | пустота/обломки/мины 1; **туманность 2**; **гравитация 2**; астероиды ∞ (непроходимы) | 16b §4.6; 15a §7.2, Прил. A.4 |
| LOS | линия по гексам (кубическая интерполяция); блокируют **астероиды и туманность**; обломки — 50%; край поля LOS не блокирует; «щель» в 1 гекс не блокирует | 16b §4.6; 15a §5.4, Прил. A.3; 15c §4.1 |
| Укрытие | цель в обломках −15% вх. урона, в туманности −10%, в пыли −5% | 16b §4.6; 15a §7.2 |
| Движение | A*/Dijkstra по стоимости; проход сквозь союзника разрешён, **финиш в занятом гексе запрещён**; сквозь врага — нельзя; MP по классу (7…2) | 16b §2.3; 15a §2.4; 15c §3.1–3.2 |
| Зоны развёртывания | **тыл/центр/фронт A = колонки 0–2**, нейтраль 3–11, **B = 12–14**; препятствий в зонах нет; макс. 7 стеков на сторону; стартовая дистанция ≥ 9 гексов | 15a §2.3–2.4 |
| Прочее | 2 стека в одном гексе запрещено; `hex_id = (r<<8)|q`; `hex_hash = hash32(seed, round, hex_id)` | 15a §2.4–2.5 |

**Типовая ошибка:** смешивать offset и axial в одном модуле (offset-таблицы соседей + cube-расстояние на тех же `q,r`, либо Manhattan по offset как «соседство») — это ломает дистанцию, соседство, LOS и дальность атаки, а значит и ИИ [15a §2.2, Прил. A.1–A.2; 15c §1.2].

## 7. Атаки и реакции

| Ситуация | Правило | Ссылка |
|---|---|---|
| Ближняя атака | цель в соседнем гексе (`dist = 1`), 1 AP, урон без штрафа дальности | 16b §4.2; 15a §5.3 |
| Дальняя атака | LOS, `dist ≤ range` (4–7), 1 AP, полный урон с места | 16b §4.3; 15a §5.4 |
| Стрельба после движения | **−25%** урона (суммируется со второй атакой: 0.75×0.85) | 16b §4.3 |
| Стрельба в упор (`dist = 1`) | **−50%** урона, цель отвечает | 16b §4.3; 15a §5.4 |
| Вторая атака в фазе | 1 AP, **−15%** урона (16b — авторитет над 16d), ответа нет | 16b §2.4, §8 п.6; 16d §1.3 |
| Ответный удар | **1 раз за раунд** на юнит; 100% урона для ближней, **50%** для стрельбы в упор; **не тратит AP** и не прерывает фазу; мёртвые не отвечают; «без ответа» — абордаж/«Тактический отход» | 16b §4.4; 15a §5.5 |
| Overwatch | 2 AP, статус до конца фазы врага, выстрел **75%** по первому движущемуся врагу в LOS/радиусе, **1 раз за фазу врага**, прерывает движение; не срабатывает на атаку/защиту без движения; ≤ 2 юнитов стороны | 16b §4.5, §2.7 |
| Порядок реакций | немедленно после действия; несколько overwatch — по **убыванию инициативы**, тай-брейк `hash`; мины — по порядку пути | 16b §4.7, §6.3 |
| Запрещено | 2 одинаковые способности за фазу; overwatch + атака в ту же фазу; отступление + другое действие | 16b §4.9 |

## 8. Победа, поражение, отступление, итог

| Исход | Условие / результат | Ссылка |
|---|---|---|
| Победа | (1) все юниты врага уничтожены; (2) враг покинул бой (преследование); (3) капитуляция — перевес FP ≥ 70% и раунд ≥ 3. **Три условия, седьмого нет** | 16b §8.1; 15a §10.1 |
| Поражение | все свои уничтожены; флот покинул бой (70% выживших); сдача (50% в плен, флагман спасён) | 16b §8.2; 15a §10.2 |

| Отступление флота | 70% кораблей, система теряется; преследование — 1 залп −15% HP, если победитель быстрее и ближе 4 гексов | 16b §8.4; 15a §10.4 |
| Итоговый экран | итог + раунды + потери по классам + FP + MVP + трофеи/XP + **полоса паритета с авторезолвом**; журнал с `phaseEnd`/`result` и checksum | 16d §10.3; 16b §8.6; 15a §12.5 |
| Конверсия | уничтожен → 40% сплавов; ранен → остаётся с %HP; сбежал → 50% HP в резерв; победа → военный счёт 0.6×(FP ratio)×10; опыт адмирала/юнита | 16b §8.5; 15a §10.5 |
| Трофеи/пленные | 40% стоимости, 20% экипажей; трофеи ≤ 15% стоимости уничтоженного флота | 16b §8.3; 15a §10.3 |

## 9. Чек-лист «это баг, а не дизайн» (по жалобам заказчика)

1. После «Завершить ход» фаза врага **пустая** или управление возвращается без вражеских действий/урона — нарушение [16b §1.4, §5.2; 16c §6.6].
2. Враг ходит «одним юнитом» или пасует, потому что этот юнит заблокирован, — фаза не должна завершаться из-за одного юнита [16b §1.4; 16e §4.6].
3. AP не списываются/не сгорают, юнит действует без AP, AP уходит в минус, AP переносится между фазами [16b §2.1, §2.9, §5.2].
4. Порядок юнитов навязан очередью по инициативе, а не выбран игроком [16b §3.3, §6.2].
5. Ответный удар не 100%/1 раз за раунд, стрельба в упор не вызывает ответа, ответ тратит AP [16b §4.4].
6. Нет штрафа −25% после движения, нет −15% за вторую атаку, нет −50% в упор [16b §4.3–4.4].
7. Соседство/дистанция считаются в offset-Manhattan или offset-таблицами вместо axial/cube — «в контакте, но атака недоступна» [15c §1.2; 15a Прил. A.2].
8. Туманность стоит 1 MP или не блокирует LOS [16b §4.6; 15a §7.2].
9. «Авто-бой»/ИИ за игрока играет иначе (хуже), чем за врага; одна сторона выигрывает всегда при зеркальном составе; паритет-число подгоняется из фактического результата [16e §4.7, §5.4; 15d §10.1; 16c §0.5].
10. Итог боя = «ничья» по кап-раунду/зависанию ИИ-цикла, а не по формуле авторезолва остатка [16b §1.8, §8.2; 16e §5.3].
